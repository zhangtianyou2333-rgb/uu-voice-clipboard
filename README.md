# UU 语音中转 · 会员复刻版

> 本仓库发布 Windows V1.12.0 / Mac V1.0.3 PublicClean 未加固复刻版，已做本地路径与凭证清理。现有代码是 Windows→Mac；Windows→Windows 需按教程新增接收端。运行包在 Releases，源码与教程在本仓库。

让一台 Windows 的豆包语音文字，通过 UU 远程的文本剪贴板同步，进入另一台电脑。

**当前提供 Windows 发送端 V1.12.0 会员预览版、Mac 接收助手 V1.0.3 源码，以及 Windows → Windows 改造教程。Windows 接收助手尚未实现。**

```text
Windows A：F12 打开输入框 → 右 Alt 启停豆包 → 文字最终确认
                           ↓
                    带标记的文本剪贴板
                           ↓ UU 远程同步
             Mac B：现有助手 → 当前应用菜单粘贴
             Windows B：会员按教程新增接收助手
```

这个项目承接输入法已识别的文字，不提供语音模型或语音识别 API。录音与识别由豆包输入法负责，跨设备连接由 UU 远程负责。

## 精简后的托盘菜单

- 打开语音输入框（F12）
- 自动转发到接收助手
- 复制诊断信息（不含输入文字）
- 关于 V1.12.0 · 会员预览版
- 退出

菜单中的“打开”也遵守 F12 的原有规则：后台找回当前会话；输入框已经在前台时请求完成。F12 不停止豆包录音。完成按钮为“完成并转发”；发送端只确认本地剪贴板交付，没有远端粘贴回执。

## 依赖与版本

- Windows x64；原使用环境是 Windows 11。其他系统版本需要单独测试。
- 豆包输入法、UU 远程、两端开启文本剪贴板同步。
- 默认输入区需要 WebView2 Runtime；运行已打包程序无需另装 .NET SDK。
- 现有源码目标 `net7.0-windows`，输入区 SDK `Microsoft.Web.WebView2 1.0.4258.31`。
- Mac 参考接收端最低 macOS 13，构建使用 Swift 5.9 或兼容工具链。

.NET 7 已结束支持；这份包先保留旧工程基线。继续维护时，建议在独立步骤迁移到 .NET 10 LTS，再重新验证输入法和双机链路，避免把框架迁移与接收端改造混成一次变更。参见[微软支持策略](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)。
