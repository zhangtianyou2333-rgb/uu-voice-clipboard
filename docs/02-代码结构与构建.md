## 构建现有 Windows 发送端

安装与旧基线兼容的 .NET SDK。现有目标是 .NET 7；它已结束支持，正式继续维护前安排单独升级。不要只改项目目标版本就声称完成迁移。

```powershell
dotnet restore 04-native-csharp/UUVoiceClipboard.Native/UUVoiceClipboard.Native.csproj
dotnet build 04-native-csharp/UUVoiceClipboard.Native/UUVoiceClipboard.Native.csproj -c Release
dotnet run --project 04-native-csharp/Tests/EntryPolicyTests/EntryPolicyTests.csproj -c Release
powershell -NoProfile -File 04-native-csharp/scripts/build-windows.ps1
```

发布脚本固定 win-x64，输出到 `04-native-csharp/publish/v1.12.0/`，安装包输出到 `02-deliverables/`。已有同版本产物会拒绝覆盖。ARM64 没有作为本次交付目标验证；项目中的加载器复制路径也是 x64，不能只改发布参数就当成支持 ARM64。

自包含包仍需单独存在 WebView2 Runtime，参见[微软分发说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。SDK、Runtime、WebView2Loader.dll 是不同组件。

## Mac 参考接收端（只在 Mac 执行）

```sh
cd 05-mac-assistant
zsh run-tests.sh
zsh build-mac-assistant.sh
```

Mac 发布脚本会构建 arm64 与 x86_64 合并包并做临时签名。构建与策略检查不等于辅助功能权限、UU 同步和实际菜单粘贴已验收。

## 开发 Windows 接收端

建议新增 `06-windows-receiver/`，保留独立项目、独立托盘和独立自测。先确定真实机器上的 UU 同步保留后缀，再选择 V1 兼容协议或独立升级协议。不要一开始重写输入法适配代码。
