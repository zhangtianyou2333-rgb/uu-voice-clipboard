# Windows → Windows 改造说明

## 目标与推荐架构

A 在本机使用豆包，A 通过 UU 控制 B，文字最终进入 B 的当前输入框。推荐保留现有发送端和 UU 同步，新增 Windows B 的接收助手。这里的跨设备能力依赖 UU，不是无需远程软件的独立网络输入法。

先复用现有协议、先手动粘贴，再开发自动粘贴。不要重新尝试在 A 给 UU 窗口模拟 Ctrl+V：原项目在这个路径上反复遇到软件注入与实体按键表现不同的问题。

## 本包精简版与旧基线的区别

V1.12.0 已删除旧多通道选择、InputInterceptor 依赖、驱动安装/诊断、Raw 右 Alt 实验入口；统一为“自动转发到接收助手”。勾选时发带标记文字，取消时复制纯文本。无需打开旧版的“Mac 助手自动粘贴”选项。

若研究原 V1.11.4：它只有 `macAssistantMode && autoPaste` 同时为 true 才加标记；只改菜单名称不能等价完成接收端改造。

## 当前兼容协议 V1

见 `MacAssistantProtocol.cs`：`正文 + START + END`，不是 JSON，也没有消息 ID。

```text
START = U+2063 U+200B U+200C U+200D
END   = U+2060 U+200D U+200C U+200B
```

接收端只在尾部完全匹配这八个码位、解出非空文字时处理。普通剪贴板文本必须忽略。标记仅区分用途，不能认证发件人，也不能证明 UU 已传输。

先验证当前 UU 版本是否原样保留这八个码位。若被裁掉，记录具体两端版本及收到的码位，不要继续盲调按键或延时；再讨论有版本号的封装协议，修改两端并单独验证。

## 接收助手分阶段实现

1. **只观察**：独立 WinForms 托盘程序，STA UI 线程；用 AddClipboardFormatListener / WM_CLIPBOARDUPDATE 监听，启动时记录当前剪贴板序号，忽略启动前的旧内容。剪贴板忙时有界重试并确认序号未被新内容替代。
2. **只清理**：严格识别标记，去除后缀，再次检查原剪贴板序号/内容仍一致后写入干净文字。记录自己写入后的序号，忽略自己的通知。清理后的普通文本即便被 UU 回流也不应再触发。先在 B 记事本手动 Ctrl+V，确认全文。
3. **手动触发**：用户在 B 的输入框放好光标，通过接收助手热键请求一次粘贴。避免点击托盘菜单抢走原输入焦点。等待后重新校验原前台应用/PID与焦点信息、剪贴板和开关；任一变化就取消，保留文字供手动操作。
4. **自动插入**：在 B 本地调用 SendInput 发送一次完整 Ctrl 按下、V 按下/抬起、Ctrl 抬起序列。这是向 B 的本地应用输入，与在 A 向 UU 注入按键是两条不同路径；仍需实测兼容。按键部分成功也可能留下状态不确定，不能自动再发另一套粘贴通道。
5. **异常与发布**：普通/管理员权限窗口分别验证；不靠默认管理员运行解决一切。UIPI 会限制跨完整性级别注入，失败时保留干净文字并提示手动粘贴。完成验收后才加可选开机启动和发布包。

## 重复、焦点与安全回退

V1 没有跨设备唯一 ID。可以按“剪贴板变更序号 + 当前会话状态”防止同一个到达事件重复处理；重复通知与真正的新变更要分开。用户连续说两遍相同句子是两次有效输入，不要永久按内容哈希去重。收到相同内容的新序号，在 V1 中无法可靠区分 UU 重放与用户重说，所以不要承诺跨重连恰好一次。

自动模式必须有明确开关；目标无效、用户切换窗口、剪贴板被覆盖、接收端停用、进入密码框或无法可靠判断目标类型时，停止自动插入，改为手动。不要用模拟点击强行恢复输入焦点，也不自动按 Enter 发送聊天消息。

若要更强的去重，再设计可选 V2：版本、packetId、senderSession、direction、正文和限期，接收端记录已处理 ID，先防回流；两端同时升级，保留旧 Mac 的独立兼容路径。它属于后续设计，不是现有代码功能。

## 可参考的 Mac 思路

`main.swift` 中的 clipboard changeCount、busy/session、写前校验和目标检查，以及 `FocusReturnPolicy.swift` 的有限恢复边界都可以参考。macOS 的 NSPasteboard、NSWorkspace、AX 菜单不能直接用于 Windows，需要分别换成 Windows 的剪贴板事件、前台/焦点检查和本地粘贴实现。

## 必须交出的证据

能编译、剪贴板有字、SendInput 返回事件数，都不能单独证明 B 的应用已输入。按验收清单记录 B 的实际完整文字、重复数和焦点变化。日志只记录阶段/计数/耗时，不记录正文。

官方依据：[剪贴板更新消息](https://learn.microsoft.com/en-us/windows/win32/dataxchg/wm-clipboardupdate)、[SendInput 与 UIPI](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。
