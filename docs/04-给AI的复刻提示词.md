# 给 AI 的复刻提示词

先解压源码，并让 AI 的工作目录指向 `uu-voice-clipboard`，再复制以下整段。

```text
请基于当前项目，新增 Windows → Windows 的接收助手。

先阅读 AGENTS.md、README.md、docs/03-Windows到Windows改造.md、docs/07-版本与精简说明.md，以及：
- 04-native-csharp/UUVoiceClipboard.Native/PasteDispatcher.cs
- 04-native-csharp/UUVoiceClipboard.Native/ClipboardRelay.cs
- 04-native-csharp/UUVoiceClipboard.Native/MacAssistantProtocol.cs
- 05-mac-assistant/Sources/UUVoiceClipboardMacAssistant/main.swift
- 05-mac-assistant/Sources/UUVoiceClipboardMacAssistant/FocusReturnPolicy.swift

场景：Windows A 本机使用豆包语音，A 用 UU 控制 Windows B；最终在 B 当前输入框插入完整识别文字。UU 负责文本剪贴板同步。现有源码是发送端 V1.12.0 会员预览版，Windows 接收端尚不存在。

先说明你读到的真实数据流和协议、准备新增的项目及验证步骤，再实现第一阶段。优先新增独立 06-windows-receiver 工程，当前受支持的 .NET LTS 可用于新工程；迁移旧发送端应单独安排，避免改变输入法行为。

第一阶段只监听、严格识别零宽后缀、清理剪贴板并让用户手动粘贴，不自动向应用输入。先请我在两台机器上验证 UU 是否保留后缀及正文。根据实际测试结果再增加手动热键粘贴，最后增加默认关闭的自动粘贴开关。

约束：
1. 保留 A 的 F12、右 Alt、WebView2、composition 和最终稳定保护。不要重写识别器，不要加麦克风或云 API。
2. 不恢复 A 向 UU 注入 Ctrl+V、模拟点击、虚拟键盘驱动、Raw 右 Alt 或旧输入框切换；这些都已从分享版移除。
3. Windows 接收端用 STA 消息循环与剪贴板监听，读取失败有界重试；启动不处理旧剪贴板；普通复制不触发。
4. 写入清理文字前校验序号与内容，处理自己写入产生的新通知和 UU 双向回流。
5. 同一个到达事件最多派发一次；用户两次说相同句子仍可各自输入。V1 无 packetId，不能声称可在所有重连情况下恰好一次。
6. 目标/焦点改变、用户输入、剪贴板被覆盖、窗口关闭或权限不匹配时取消自动动作。自动模式遇到密码框/目标类型不明时回退手动。不自动按 Enter。
7. 不把 SendInput 返回或本地交付显示成远端已插入；无确认时明确标为未确认，不重试不确定的粘贴。
8. 日志不含正文、剪贴板全文和窗口标题。不要上传仓库、安装驱动或修改账户。
9. 给出相关策略检查、可构建源码、独立运行包和实际双机验收表。凡未在 Windows 两台真机运行的结果，都标“待实机验证”。

每阶段给我具体测试步骤和需要回报的信息，取得真实结果后再推进依赖它的下一阶段。
```

```text
普通文本同步：通过 / 不通过
八个零宽码位是否完整：是 / 否 / 尚未检测
B 手动粘贴全文：通过 / 不通过
短句与长句、中文和 emoji：
当前错误码/阶段（不要粘贴私人正文）：
```
